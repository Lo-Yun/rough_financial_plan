## 2. 決策紀錄

重要決定與理由，避免日後重複討論。編號沿用規格書第 10 節。

| 編號 | 決定 | 理由 | 何時 |
|---|---|---|---|
| D1 | 財富階梯台灣門檻用**匯率換算**（30 萬／300 萬／3,000 萬／3 億／30 億） | 簡單好懂；門檻放在地區資料包，日後可換 | 規劃 |
| D2 | 區間採**保守的區間算術**，畫面以中間值為主、範圍為輔；比率避免同一個不確定性算兩次 | 誠實呈現粗估；實測後主要的寬度來自使用者自己輸入的範圍 | P2 |
| D3 | 自住房**計入淨值**與財富階梯；可動用淨值不計入 | 與 Maggiulli 原書一致 | 規劃 |
| D5 | **不收集任何使用統計** | 隱私優先；CSP 的 `connect-src 'self'` 確保網頁無法把資料送出去 | P1 後 |
| D8 | 形式為 **PWA**，資料只存在裝置上，不需註冊 | 入門門檻最低、最容易信任 | 規劃 |
| D9 | 先做台灣，但台灣專屬數值全部放在**地區資料包** | 保留日後推向海外的彈性 | 規劃 |
| D10 | 部署用 **GitHub Pages**（原本規劃 Cloudflare Pages） | 可以完全在 GitHub 內自動化；代價是不能設定回應標頭（改用 `<meta>` CSP，少了防嵌入保護） | P1 後 |
| D11 | 名稱：大概理財 → 隨便理財 → **順便理財** | 使用者決定 | P1 後、P3 後 |
| D12 | 對帳檢查比較**中間值**，不用「範圍重疊」 | 粗估範圍很寬、幾乎都會重疊，檢查會失去意義 | P2 |
| D13 | 投資配置用 **100% 堆疊長條＋表格**，不用圓餅圖 | 依資料視覺化準則，比較「目前 vs 目標」較清楚；顏色經色盲檢查 | P3 |
| D14 | 投資組合**預設不含現金** | 現金多半是緊急預備金；使用者可勾選納入 | P3 |
| D15 | 只提供**通用原則**，不推薦任何特定商品 | 避開投信投顧法規範 | 規劃 |
| D16 | 行動「建議」由規則**即時計算、不儲存**；只儲存使用者處理過的紀錄 | 規則或資料改變時，建議自動更新，不會留下過時的建議 | P4 |
| D17 | 回顧提醒只在 App 內顯示，**暫不做推播** | Web Push 需要伺服器，與「沒有後端」的原則衝突 | P4 |
| D18 | 行動規則依 Maggiulli 的分層調整重點：L1–L2 提升收入、L3 避免生活風格膨脹、L4+ 資產保全 | 對應原書「不同層級用不同策略」的觀點（文字待對照原書，見 T2） | P4 |

## 4. 下一步：P5 候選項目

規格書的四期都已完成。以下是建議的下一批工作，依「讓真實使用者能放心用」的重要程度排列，實際順序由使用者決定。

1. ~~**內容校對**（T1、T2）~~：✅ 已完成（財富階梯仍建議有原書時逐句對照）。
2. **示範資料模式**（T7）：一鍵載入虛構家庭的資料試玩，不影響真實資料。方便介紹給朋友，也方便測試。
3. **白話教育內容**：每個指標與名詞的短文說明，從健檢、行動建議的「為什麼」連過去。
4. **PIN 碼鎖**（T7）：防止旁人打開 App 看到資料（不是強加密）。
5. **歷史圖表改輕量**（T10）。
6. **回顧推播**（D17）：需要評估是否接受一個極簡的推播伺服器。

## 5. 未來方向（P5 之後）

尚未排定，依使用者回饋決定先後。

**資料與同步**
- 加密雲端同步（端對端加密，伺服器看不到內容），支援多裝置。
- 夫妻／家庭共用：資料模型已預留成員欄位。
- 從記帳 App（如 CWMoney、Moneybook）匯入 CSV，用實際紀錄校正收支估算。

**更精確的計算**
- 股價與匯率自動更新（需要報價 API；要注意授權與 CSP 例外）。
- 勞保年金、勞退納入退休計畫（規格 D4）。
- 稅務粗估（所得稅、房屋稅）。
- 保險健檢：保額 vs 年收入（雙十原則的另一半）、儲蓄險解約金 vs 已繳保費。
- 退休計畫的蒙地卡羅模擬（以機率呈現達成可能性）。

**體驗與留存**
- 示範資料模式、PIN 碼鎖（T7）。
- 白話的教育內容：每個指標、每個名詞的短文說明。
- 里程碑與成就（存滿緊急預備金、升上財富階梯下一層）。

**國際化**
- 新增其他地區資料包（例如美國：401(k)、IRA、28/36 規則、美元門檻）與英文介面。
- 語言與地區分開設定。
