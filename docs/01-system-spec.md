## 1. 產品定位

### 1.1 一句話

**用「大概的數字」就能看懂自己的財務狀況、算出理財計畫，再一步步把數字變精確、把財務變更好。**

### 1.2 目標使用者

| 類型 | 描述 | 痛點 | 我們提供 |
|---|---|---|---|
| A. 理財新手 | 不懂理財或投資，沒記帳習慣 | 一打開理財工具就要填一堆精確數字，直接放棄 | 5 分鐘粗估、白話解釋、紅黃綠燈 |
| B. 有心但動力不足 | 知道該理財，但一直沒行動 | 不知道下一步該做什麼，也看不到進度 | 財富階梯定位、行動清單、淨值成長曲線 |

### 1.3 不做的事（Non-goals）

- **不做逐筆記帳**：價值在於「不用記帳也能掌握全貌」。
- **不推薦特定金融商品**（個股、基金、保單）：避開投顧法規，只提供通用原則與教育內容。
- **初期不串接銀行或券商帳戶**：不需要帳號、不上傳資料，降低信任門檻。
- **初期不提供即時報價**。

## 2. 設計原則

1. **先粗後精**：所有數字都可以用「不知道／區間／大約／精確」四種精確度輸入。
2. **單一資料來源**：四大工具共用同一份財務資料，任何數字只輸入一次。
3. **結果誠實呈現**：輸入是粗估，結果就用「中間值 + 區間」呈現，並附上整體精確度。
4. **白話優先**：每個指標都有一句話解釋「這代表什麼」和「可以怎麼做」。
5. **隱私優先**：資料只存在使用者的裝置上，沒有後端、不用註冊。
6. **在地化可抽換**：台灣專屬的規則、統計數據、門檻、文字，都放在「地區資料包（Locale Pack）」，核心程式不寫死台灣邏輯，以利日後推向海外。

## 4. 功能規格

### 4.1 快速估算引導（Onboarding）— P1

目標是首次使用 **5 分鐘內** 看到第一個結果。

1. 歡迎頁：說明資料只存在本機，以及「不確定也沒關係，先估個大概」。
2. 基本資料：出生年（可選區間）、家庭型態（單身／夫妻／有小孩）、居住縣市（可選，用來帶入統計預設值）。
3. 約 10 個問題，每題都可以選「不知道」：
   - 每月大約收入（級距按鈕）、每年年終／獎金大約幾個月
   - 每月大約花費（級距按鈕；選「不知道」就依家庭型態帶入統計值）
   - 現金與存款大約多少
   - 有沒有投資？大約多少
   - 有沒有房子或車子？大約價值多少
   - 有沒有房貸、車貸、信貸、卡債、學貸？大約還欠多少
4. 結果頁：淨值區間、精確度、每月大約可存多少、財富階梯層級與往下一層的進度（行動建議在 P4）、「下一步」說明。

### 4.2 估算輸入元件（EstimateInput）— P1，全 App 共用

| 模式 | UI | 說明 |
|---|---|---|
| 不知道 | 「不確定」按鈕 | 用地區資料包的統計值代入，以 P25～P75 當區間 |
| 區間 | 級距按鈕或雙端滑桿 | 級距定義在地區資料包 |
| 大約 | 數字輸入 + 「約」標籤 | 預設誤差 ±15%（可在設定中調整） |
| 精確 | 數字輸入 + 「精確」標籤 + 日期 | 誤差 0；超過「過期天數」後提醒更新 |

- 模式可以隨時切換，切換時保留可沿用的數值（例如區間切成大約時，帶入中間值）。
- 每個欄位旁邊顯示精確度小圖示（空心圓 → 實心圓）。
- 支援幣別選擇（預設新台幣），並支援「萬」為單位輸入（例如輸入 `600萬`）。

### 4.3 收支估算 — P2

- 收入項目：薪資、年終與獎金、副業、營業收入、租金、股利利息、退休金或年金、其他。
- 支出項目分類（台灣預設，參考主計總處家庭收支調查的分類）：
  居住（房租、管理費、水電瓦斯）、飲食、交通、通訊、保險費、子女教育、醫療、孝親費、娛樂與旅遊、購物、**年度不定期支出**（紅包、稅、保養、旅遊）、其他。
- 每個項目都有頻率（每月、每季、每年、每週），系統統一換算為月與年。
- **貸款還款不在支出裡輸入**，由負債的「每月還款」自動計入現金流，避免重複計算。
- 提供「對帳檢查」：估算的年結餘，跟使用者回答的「過去一年存款大約增加多少」比較**中間值**，差距超過 30% 就提醒「可能低估了支出」（並列出常被忘記的支出）或「可能低估了收入」。不用「範圍有重疊」判斷，因為粗估的範圍幾乎都會重疊。

### 4.4 資產負債表與淨值 — P1

- 資產分類：現金與存款、投資（股票、ETF、基金、債券）、加密資產、退休帳戶（勞退個人專戶等）、儲蓄險（解約金）、不動產、車輛、應收款、其他。
- 負債分類：房貸、車貸、信貸、信用卡（循環）、學貸、親友借款、經營借款、其他。
- 每筆資產都有**流動性**（可立即動用、需時間變現、難以變現），用來計算「可動用淨值」。
- 畫面：
  - 淨值總覽（中間值大字，區間小字，加上精確度環）
  - 資產與負債兩欄列表，可展開分類
  - 「淨值」與「可動用淨值（不含自住房、車、退休帳戶）」切換
  - 淨值歷史曲線（以快照建立；區間用陰影帶呈現）
- **快照**：使用者按「記錄這個月」，或完成定期回顧時建立；同一天只保留最後一筆。

### 4.5 財務健檢 — P2

每個指標都包含：數值（區間）、燈號、一句白話解釋、建議動作連結。門檻值放在地區資料包，以下為台灣預設：

| 指標 | 公式 | 🔴 | 🟡 | 🟢 |
|---|---|---|---|---|
| 儲蓄率 | 1 − (月支出 + 月還款) ÷ 月收入 | < 0% | 0–10% | ≥ 10%（≥ 20% 優秀） |
| 緊急預備金月數 | 可立即動用資產 ÷ (月支出 + 月還款) | < 1 | 1–3 | 3–6（> 12 提示可能閒置） |
| 還款負擔比（DSR） | 月還款 ÷ 月收入 | > 40% | 30–40% | < 30% |
| 居住成本比 | (房租或房貸月付 + 管理費) ÷ 月收入 | > 40% | 30–40% | < 30% |
| 高利負債 | 年利率 ≥ 8% 的負債餘額 | > 0（卡債循環一律紅燈） | — | 0 |
| 無擔保負債倍數 | 無擔保負債 ÷ 月收入（台灣 DBR 22 倍規範） | > 22 | 15–22 | < 15 |
| 保費負擔 | 年保費 ÷ 年收入（雙十原則） | > 20% | 10–20% | ≤ 10% |
| 財務自由進度 | 可投資資產 ÷ 財務自由目標金額 | — | — | 進度條 |

- 燈號依據區間的**中間值**判定；如果區間橫跨兩個燈號，標示「可能是🟡或🟢，填精確一點就知道」。
- 數值顯示「約 中間值」，範圍放在下一行小字。
- 缺少計算所需的資料時（例如沒填收入、沒有房租或房貸、沒填保費），該指標顯示「無法計算」與原因，不給燈號。
- 月還款：使用者填的每月還款；沒填時依利率（沒填用地區資料包的預設利率）與預設剩餘期數推算。每月全額繳清的信用卡不算還款也不算高利負債（帳單已在支出中）。
- 健檢頁最上方是「最該先處理的一件事」，依優先順序挑出最嚴重的指標。

### 4.6 理財計畫（目標試算）— P2

- 目標類型：緊急預備金、還清債務、買房頭期款、退休／財務自由、子女教育金、大筆消費、自訂。
- 每個目標包含：目標金額（可粗估）、目標日期、優先順序、已指定的資產（選填）。
- 試算輸出：
  - 「每月需要存多少」（PMT）
  - 「照目前存錢速度，大約何時達成」（區間：最早～最晚）
  - 用不同報酬率假設比較（保守、中性、樂觀）
- 內建試算器：
  - **財務自由數字** = 年支出 ÷ 安全提領率（台灣預設 4%，可調整為 3.5%）
  - **買房**：總價 × 自備比例（預設 20%）＋ 雜費（預設 3%），並估算房貸月付是否超過居住成本比的門檻
  - **還債**：雪崩法（先還高利率）與雪球法（先還小額）的比較：還清月數、總利息、還清順序
- 計算一律用**實質報酬**（名目報酬 − 通膨），結果都以今天的幣值呈現，降低理解難度。
- 報酬率依「這筆錢怎麼放」分三類：存款（短期目標）、股債平衡（3～10 年）、積極成長（10 年以上），預設依目標類型帶入。
- 每月投入：使用者有設定就用設定值，否則用目前的每月結餘試算；多個目標共用結餘時會提醒要分配。
- 編輯目標時即時顯示試算結果。

### 4.7 投資組合儀表板 — P3

- 資料來源就是資產負債表中的投資類資產，不需重複輸入。
- 每筆投資資產可以：
  - 只指定一個資產類別（最粗）
  - 指定各類別的百分比（例如「0050 + 債券 ETF 大約 7:3」）
  - （選用）輸入持股明細：代號、股數、成本、手動輸入的現價
- 資產類別：現金、台股、全球股票、債券、不動產（REITs）、加密資產、儲蓄險、其他。
- 列入投資組合的資產：投資、加密資產、退休帳戶、儲蓄險；現金與存款由使用者決定是否列入（預設不列入，因為多半是緊急預備金）。
- 配置的優先順序：持股明細 → 使用者指定的比例 → 地區資料包的類別預設值。投資帳戶與退休帳戶的預設值只是猜測，畫面會提醒使用者確認。
- 持股明細可用「股數 × 手動輸入的現價」或「直接估市值」；帳戶可設定「用持股加總當作帳戶價值」，修改持股時自動更新。
- 畫面：
  - 配置以 **100% 堆疊長條**呈現（目前 vs 目標），比較股票、債券、現金、其他四大類，旁邊附數字表格；細項類別可展開。依資料視覺化準則，組成比例用堆疊長條而不用圓餅圖，顏色取自經驗證的色盲友善類別色，並一定附表格，不單靠顏色辨識。
  - 目標配置：保守（股 30／債 50／現金 20）、穩健（60／30／10）、積極（85／10／5）、「110 − 年齡」（需要出生年）、自訂。
  - 偏離提示：任一大類偏離超過 ±5 個百分點就提示再平衡，並顯示約略金額；只給通用原則（先用新投入補足），不建議買賣特定商品。
  - 單一持股集中度警示（超過整體 20%）。
  - 粗略的風險等級：依股票比例加上 1.5 倍的加密資產比例，分為 5 級。
  - 幣別分布（有外幣時）。
- 配置比例一律用中間值計算。
- **不提供**買賣特定商品的建議。

### 4.8 財富階梯（Maggiulli《The Wealth Ladder》）— P4

依淨值分為 6 層，每層約 10 倍。原書以美元定義，台灣版的門檻值放在地區資料包。

| 層級 | 原書（USD） | 原書命名 | 台灣門檻（方案 A，已決定） | 核心焦點（本 App 的詮釋） |
|---|---|---|---|---|
| L1 | < $10k | Paycheck-to-paycheck | < 30 萬 | 穩定現金流、清掉高利債、建立小額緊急金 |
| L2 | $10k–$100k | Grocery freedom | 30 萬–300 萬 | 緊急金滿 3–6 個月、提高收入、開始定期投資 |
| L3 | $100k–$1M | Restaurant freedom | 300 萬–3,000 萬 | 提高儲蓄率、資產配置、退休規劃、避免生活風格膨脹 |
| L4 | $1M–$10M | Travel freedom | 3,000 萬–3 億 | 資產保全、稅務、傳承、再平衡紀律 |
| L5 | $10M–$100M | House freedom | 3 億–30 億 | 建議尋求專業顧問（超出 App 範圍） |
| L6 | $100M+ | Philanthropic freedom | > 30 億 | 同上 |

> 原書的層級命名與各層策略，需要在實作前對照原書校對。

- **台灣門檻（已決定：方案 A）**：依匯率（約 1 USD ≈ 30 TWD）取整，即上表。
  - 曾考慮的其他方案：依購買力平價（門檻 15 萬／150 萬……），或以家戶淨值分位數定義。
  - 門檻一律由地區資料包提供，日後要換方案只需要改資料。
- **淨值計算（已決定）**：階梯層級使用含自住房的總淨值，與原書一致。
- **負淨值**：歸在 L1，另外標示「負債大於資產」，行動建議優先處理債務。
- 使用者看到：
  - 目前層級，以及淨值區間如果跨兩層，就標示「介於 L2 與 L3 之間」
  - 到下一層的進度（**對數尺度**，因為每層是 10 倍）
  - 照目前的存錢速度與報酬假設，**大約幾年到下一層**（區間）
  - 「0.01% 法則」：日常小額花費低於淨值 × 0.01% 時，不必為此焦慮（原書概念）

### 4.9 行動建議與追蹤 — P4

- **規則引擎**：`條件（健檢指標、階梯層級、資料精確度）→ 行動範本`。規則與範本都放在地區資料包。
- 範例規則：
  - 有卡債循環 → 「先還清信用卡循環餘額」（最高優先）
  - 緊急預備金 < 1 個月 → 「每月先存 X 元，存到 1 個月生活費」
  - 最大的資產或負債還是「不知道」 → 「花 2 分鐘查一下房貸餘額」（提高精確度本身就是一種行動）
  - L2、緊急金已足、儲蓄率 ≥ 10%、沒有投資 → 「了解指數化投資與定期定額」（教育內容，不推薦商品）
- 使用者可以：接受、略過（附原因）、標記完成；也可以新增自訂行動。
- 同時進行中的建議最多 3 項，避免壓力過大。

### 4.10 定期回顧（Check-in）— P4

- 頻率：每月（預設）或每季。PWA 支援時發送推播，不支援時在 App 內提醒。
- 流程（目標 1 分鐘內完成）：
  1. 「這個月有大變化嗎？」有的話才進入修改
  2. 快速更新：只列出最大的 3 項資產和負債，以及過期的精確數字
  3. 行動進度打勾
  4. 自動建立快照，並顯示與上次比較的淨值變化
- 連續回顧的次數以溫和的方式呈現，不做懲罰性設計。

### 4.11 設定、備份、資料管理 — P1

- 設定：主要幣別、匯率（手動輸入，記錄更新日期）、預設誤差、報酬與通膨假設、回顧頻率、語言。
- **備份匯出**：JSON 檔，可選擇用密碼加密（AES-GCM，金鑰以 PBKDF2 衍生）。
- **匯入**：會先檢查 schema 版本並自動遷移。
- **定期備份提醒**：每 30 天，或資料有重大變動時提醒。
- **刪除全部資料**：需要二次確認。
- 示範資料模式：載入一組虛構家庭的資料來試玩，不影響真實資料。

## 5. 計算規則

### 5.1 估算值 → 區間

每個估算值都會解析成 `{ low, mid, high }`：

| 模式 | low | mid | high |
|---|---|---|---|
| 不知道 | 統計 P25 | 統計 P50 | 統計 P75 |
| 區間 | low | (low + high) / 2 | high |
| 大約 | v × (1 − t) | v | v × (1 + t)，t 預設 0.15 |
| 精確 | v | v | v |

- 「不知道」但沒有對應的統計值（例如房子價值）時，該項目**不納入計算**，並在結果上標示「有 N 項未知」。

### 5.2 區間運算

- 加總：`low = Σlow`，`high = Σhigh`。
- 相減（淨值 = 資產 − 負債）：`low = A.low − L.high`，`high = A.high − L.low`。
- 比率：取最不利與最有利的組合，再限制在合理範圍。
- 採**保守的區間算術**，代表最壞與最好的情況。
- 比率要避免同一個數字的不確定性被算兩次（例如儲蓄率用「1 − 流出 ÷ 收入」，而不是「結餘 ÷ 收入」）。
- 實測後區間主要來自使用者輸入的範圍本身，維持保守算術；主要數字一律顯示中間值。若日後仍覺得太寬，再考慮「誤差獨立假設」。
- 主要數字一律顯示 `mid`，區間用小字或陰影帶呈現。

### 5.3 精確度分數

```
precision = Σ( |mid_i| × w(mode_i) ) / Σ |mid_i|
w: 不知道 = 0、區間 = 0.4、大約 = 0.75、精確 = 1.0
```

- 依金額加權：把房子從「大約」改成「精確」，比把手機費改成精確更能提高分數。
- **過期衰減**：精確數字超過地區資料包設定的天數（預設 180 天）後，權重降為大約（0.75）。
- 分數分為整體、資產負債表、收支三個層級。

### 5.4 頻率換算

月 = 週 × 52 / 12；季 ÷ 3；年 ÷ 12。年終獎金等一次性收入，換算成月平均後計入儲蓄率，但緊急預備金只用經常性收入計算。

### 5.5 幣別

- 所有計算先換成主要幣別。匯率為使用者手動維護，並記錄日期。
- 外幣資產的匯率風險，P3 以後在投資組合中顯示幣別分布。

### 5.6 預設假設（台灣，可調整）

| 假設 | 預設值 |
|---|---|
| 通膨 | 2.0% |
| 股票名目報酬（保守／中性／樂觀） | 5% / 7% / 9% |
| 債券名目報酬 | 3% |
| 現金與存款報酬 | 1.5% |

## 6. 技術架構

### 6.1 技術選型

| 項目 | 選擇 | 理由 |
|---|---|---|
| 語言 | TypeScript（strict） | 財務計算需要型別安全 |
| 框架 | React 18 + Vite | 生態系完整、建置快 |
| PWA | vite-plugin-pwa（Workbox） | 離線快取、安裝提示 |
| 本機資料庫 | IndexedDB，透過 Dexie.js | 支援 schema 版本遷移與索引 |
| 狀態管理 | dexie-react-hooks（`useLiveQuery`） | 資料庫即狀態，寫入後畫面自動更新；P1 不需要額外的狀態管理套件 |
| 圖表 | Recharts（或 ECharts） | 圓餅、折線、區間帶 |
| 國際化 | i18next | 文字與數字格式化抽離 |
| 測試 | Vitest（計算核心）+ Playwright（E2E） | 計算核心要求高覆蓋率 |
| 部署 | GitHub Pages（見 [部署說明](./03-deploy-github-pages.md)） | 沒有後端，免費；合併到 main 自動部署 |

### 6.2 分層

```
┌─────────────────────────── UI（React 頁面與元件）────────────────────────────┐
│ Onboarding │ 淨值 │ 收支 │ 健檢 │ 計畫 │ 投資組合 │ 階梯 │ 行動 │ 回顧 │ 設定 │
├──────────────────────── 應用層（Zustand stores、use-cases）──────────────────┤
│ 讀寫 repository、觸發重新計算、建立快照、執行規則引擎                          │
├──────────── 計算核心 src/core（純函式，不依賴 React、瀏覽器）─────────────────┤
│ estimate │ interval │ cashflow │ balance │ health │ planning │ portfolio │ ladder │ rules │
├───────────────────── 資料層 src/data（Dexie repository、遷移）─────────────────┤
├───────────────────── 地區資料包 src/locales/<code>/（純資料 JSON 或 TS）───────┤
└──────────────────────────────────────────────────────────────────────────────┘
```

- **計算核心不得引用地區相關常數**，一律由呼叫端傳入地區資料包。這是日後國際化的關鍵。
- 計算核心不碰 IndexedDB，方便單元測試，未來也能搬到 React Native 或伺服器端。

### 6.4 離線與儲存可靠性

- App 殼與地區資料包都由 Service Worker 快取，完全離線可用。
- **啟動時呼叫 `navigator.storage.persist()`** 申請持久化儲存。
- **iOS Safari 風險**：網站如果沒有加入主畫面，連續 7 天沒有使用時，瀏覽器可能清除網站資料。對策：
  1. 首次使用時就引導使用者「加入主畫面」
  2. 偵測未安裝時顯示提示條
  3. 定期備份提醒
- 資料寫入採交易方式，避免寫到一半損毀。

## 7. 在地化與國際化策略

「只做台灣、保留彈性」的作法，是把所有地區差異集中到 **地區資料包（LocalePack）**：

| 地區資料包內容 | 台灣範例 | 外國替換範例 |
|---|---|---|
| 主要幣別、數字格式 | TWD，以「萬」為單位 | USD，以 k 為單位 |
| 輸入級距 | 月薪 3 萬以下、3–5 萬…… | Under $3k…… |
| 統計預設值 | 主計總處家庭收支調查（依家庭型態） | BLS Consumer Expenditure Survey |
| 收支、資產、負債分類 | 孝親費、勞退個人專戶、儲蓄險 | 401(k)、Roth IRA、HSA |
| 健檢門檻 | DBR 22 倍、雙十原則 | 美國常用的 28/36 rule |
| 財富階梯門檻 | 30 萬／300 萬…… | $10k / $100k…… |
| 行動規則與範本、教育內容 | 台灣版 | 當地版 |
| 預設假設 | 通膨 2% 等 | 當地值 |

- UI 文字一律透過 i18n key，不寫死中文。
- 分類使用**穩定的英文 key**（例如 `family_support`），顯示名稱由 i18n 提供。
- 使用者資料記錄 `localeCode`；日後跨國搬遷時，可以換地區資料包但保留資料。

## 8. 隱私、安全與法規

- **沒有後端，也不收集任何個資**。
- **不收集任何使用統計（已決定）**：App 不會對外送出任何資料，也沒有第三方追蹤程式碼。
- 匯出檔可以加密；App 內可設定 PIN 碼鎖（P2，僅用於防止旁人偷看，不是強加密）。
- **免責聲明**：首次使用及計畫、投資頁面都要清楚標示「本工具提供一般性財務教育與估算，不構成投資建議」。
- **投信投顧法**：
  - 行動建議與教育內容只講原則和工具類別（例如「指數化投資」、「定期定額」），不點名商品。
  - 上線前建議諮詢律師確認。
- 統計資料要註明來源與年份。
